# B2.6 implementation and security evidence

## Scope and evaluation status

This frontend change restores Creator Detail performance cards, the calendar, period-scoped
content tabs and access-state display. It uses existing creator, content and invoice endpoints.
No dependency, backend source, API contract, database, authentication or authorization change was
made.

The repository and the searched workspace project folders did not contain the B2.6 issue text,
approved prototype, or `IR-Paduan-Evaluasi-Development.txt`. The exact score-4 rubric criteria
therefore cannot be mapped or verified here. The RED/GREEN history and evidence below are factual
artifacts for review; they do not establish an IR score or predict an assessor's result.

## OWASP Top 10:2025 review

These checks are limited to changed frontend paths and are not a full security audit. Category names
follow the [OWASP Top 10:2025](https://top10.owasp.org/2025/0x00_2025-Introduction/).

| Category | Risk and relevance | Check and safeguard |
| --- | --- | --- |
| A01 Broken Access Control | A visible action or client-side period choice must not grant permissions. | Creator detail reads remain server-side with the existing session cookie and backend admin guard. No revocation endpoint or permission rule was added. Server tests check the cookie is forwarded. The missing Cabut Akses flow is recorded as a blocker rather than simulated. See [OWASP A01](https://top10.owasp.org/2025/A01_2025-Broken_Access_Control/index.html). |
| A02 Security Misconfiguration | Weakening runtime security or introducing unsafe configuration would affect this page. | No security configuration, middleware, environment handling, or dependency files changed. Frontend lint and production build were run. |
| A03 Software Supply Chain Failures | New packages would add supply-chain exposure. | No dependency was added or changed; `package.json` and lockfiles are outside the change. |
| A05 Injection | Creator names and content titles are untrusted text; query values can be copied into URLs. | React text rendering is retained; no HTML injection API is used. Calendar and table regression tests render HTML-looking titles as text. Invoice search links use `URLSearchParams`. |
| A06 Insecure Design | Deriving sign-in permission from a contract period or presenting an unconfirmed revocation would mislead staff. | Access derives only from the existing revoke-date field and Jakarta calendar day; unknown stays unknown. No fake revoke action or success message exists. Boundary tests cover the revoke day. |
| A07 Authentication Failures | Session material must not enter client state, URLs or logs. | The existing server-only cookie forwarding path remains in place; no token is passed to client components or query strings. Server tests inspect request headers. |
| A10 Mishandling of Exceptional Conditions | Missing fields, invalid dates, failed invoice reads or failed calendar reads could produce false values or partial views. | Missing access and invoice values render as unavailable; failed calendar/content reads throw into the existing page error path. Tests cover missing data, invoice failure and calendar failure. See [OWASP A10](https://top10.owasp.org/2025/A10_2025-Mishandling_of_Exceptional_Conditions/). |

Passing unit tests does not constitute a complete penetration test or application security audit.
