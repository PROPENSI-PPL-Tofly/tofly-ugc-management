**2. Programming Best Practices, OO & SOLID Principles (CPL 6)**

*   **Principles / Patterns Applied:** Single Responsibility Principle (one pure module reads the link list's rows, URL state and query; one table draws both lists; the read-only card only renders), Dependency Inversion (seams injected as arguments, so tests stand a mock in without touching the code), Open/Closed (platform marks and labels keyed by platform — a new platform is a row in a map, not a new branch), DRY (one `link-performance-table` for creator and content lists, one shared sync call, the InfoTip reused for the H-5 explanation), Adapter pattern (the seam speaks `GET /performance/links`'s list grammar and refuses what it cannot read)
*   **Implementation Details:** `performance-links.ts` is one pure module owning rows, URL state and query — tested without a DOM and without a network. `performance-links.server.ts` is the only place that knows the API's words; it validates the answer's shape on the way in (an unusable 200 is refused), which is also exactly where the mock stands in the tests (`vi.mock("@/lib/performance-links.server")`) — the DIP boundary and the test seam are the same line. `link-performance-table.tsx` draws both lists from one column definition instead of two near-copies; `platform-icon.tsx` maps platform → mark (OCP). On 228, `ContentLink` is read as 38.1 *sends* it — nullable `platform`, `submittedAt` as a day — through one adapter, so the API's contract change was absorbed in one module and the legacy and replaced states are values, not conditionals scattered across components. Time and address state are read at the edge and passed down (`today`, parsed URL params), keeping every rule testable across midnight and boundary days.

**6. Security Awareness (CPL 6)**

*   **Security Controls Applied:**
    *   **Security screening with OWASP ZAP, in the workflow not on a whim:** the ZAP baseline scan (passive spider + passive rules, no attack payloads) runs against the built app three ways — `scripts/zap.ps1` locally, the `githooks/pre-push` gate (a push is blocked only by FAIL-level findings; warnings report; the bypass is explicit), and `.github/workflows/zap.yml` on every push — so every change gets its web-security check as it is written (OWASP A05)
    *   **Findings triaged with a severity policy:** the first scan reports **0 High, 2 Medium** (a CSP wildcard directive and `style-src 'unsafe-inline'`, both on `/api/auth/google` where the framework's default CSP serves the OAuth hand-off), **3 Low** (big-redirect information leak ×2, missing COOP/COEP ×4) and 4 informational over 21 endpoints; `.zap/rules.tsv` records what gates and why — the two transport-only checks are IGNOREd because the scan target is plain HTTP, with their return to FAIL the day the scan moves to the HTTPS staging URL (OWASP A05)
    *   **Session-scoped reads, no id in the address:** the creator's own links under Akun Terhubung come from the session — there is deliberately **no creator in the address** — so the panel cannot be pointed at another creator, and a 403 is rendered as the panel's own failure state (OWASP A01)
    *   **Read-only surfaces are pinned, not promised:** the creator's cards offer no sync and no manual input, and a `[TEST]` commit asserts it — a later button cannot quietly appear on a surface the PRD says is read-only (OWASP A01, A08)
*   **Vulnerability Mitigations:**
    *   OWASP A01 (Broken Access Control): session-derived creator scope on the read-only links, admin-gated Performa Konten, and the 403-as-failure rendering so an authorization refusal is honest rather than a blank page
    *   OWASP A05 (Security Misconfiguration): the ZAP baseline surfaces the CSP posture (wildcard font/style sources, `unsafe-inline`) and the missing COOP/COEP headers as tracked findings with an explicit severity policy instead of an untracked scan nobody reads
    *   OWASP A08 (Software and Data Integrity Failures): the seam refuses an unusable 200 before it renders — a wrong-shaped success cannot paint a wrong table — and a missing `links` field is read as an old answer, never fabricated
    *   OWASP A10 (Mishandling of Exceptional Conditions): empty, error and 403 states each render their own words ("Belum ada link yang dikirim", the panel's failure state), the sync holds its rows while running and toasts the outcome, and a replaced link reads from the payload's own flag
